## 目标与范围

让用户在 React 中找到当前服务保存的配方，打开其保存内容，并知道手动保存是否成功。
首版复用现有历史条目与模型快照，不增加文件格式、云存储或第二套配方仓库。
跨电脑工程包为所有者未选的方案 B，留到后续独立设计。

当前已有 `/api/history`、`/api/recipe/load` 和 `/api/recipe/save`；typed client 已有
loadRecipe/saveRecipe，但 React 没有打开入口，也未在状态中保留服务端 current_recipe。
现有保存按钮仅发请求，缺少成功反馈；其通用运行动作还会退出历史查看模式。
本段修正与保存/打开直接相关的状态衔接，不重做其他面板或工艺功能。

## 界面与操作

1. 在既有「配方操作」中增加「打开已保存配方 / Open saved recipe」。打开原生深色
   弹窗，沿用现有控件与局部样式，不改三栏。提供加载中、空列表、列表失败与手动刷新。
2. 列表显示名称、最近记录时间、当前条目标记及「有自动保存 / 无自动保存」状态。
   来源是当前服务的会话存储，不标称为浏览器文件、云端文件或跨电脑备份。
   按服务端 timestamp 倒序、同值按 id 稳定排序；不展示内部文件路径。
   旧条目缺少可选时间时显示「时间未知」，缺少自动保存字段时显示「状态未知」。
3. 时间戳采用现有服务端本地时间格式。只做可读排版，标注为服务端时间；无时区
   信息时不伪装成 UTC 或擅自换算。切换界面语言不会改变日期所代表的时间。
4. 选择一个条目后，显示其名称及说明：「将打开此配方的保存内容；如有较新的自动
   保存，将按现有规则恢复。不会自动重新构建。切换前服务会自动保存当前已提交内容。」
   用户点击「打开此配方」才发请求，选中列表项和刷新均不切换模型。当前条目也允许
   显式重开，但不预选并自动加载任何条目。
5. 有活动参数草稿、未完成参数保存、类型候选、运行、版图写入或导出时，禁止实际
   打开并给出处理提示；不提供静默丢弃草稿。服务端已提交而尚未手动保存的编辑沿用
   后端切换前自动保存规则，不冒充浏览器内未提交草稿已被保存。
6. 打开期间显示「正在打开」，按钮防重复，弹窗暂不可关闭。成功后关闭弹窗，更新
   当前配方名称、参数、模型和时间线；Viewer 按既有新模型刷新规则更新，不重挂应用。
   只在权威响应成功后替换当前内容，保留语言及逐字段单位偏好。
7. 配方名称输入框从服务端当前名称初始化；切换/新建/导入成功后跟随新的当前名称。
   用户正在输入名称时，列表刷新或语言切换不覆盖输入。名称规则与服务一致：trim 后
   非空，最多 80 个字符，超长明确提示，不能显示完整名称却在服务端静默截短。
8. 点击现有保存按钮后显示本地进度；仅在服务端明确 `saved=true` 后显示「已保存：
   配方名称」。重复点击只发一次。`saved=false`、异常或无可信成功证据时不得报成功。
   保存成功同时更新当前条目 identity/名称；模型、历史位置、执行结果与原工艺错误保持。
   后续参数、步骤、模型或待保存名称变动后，旧成功提示撤下，避免冒充当前已保存。
9. 沿用现有保存语义：修改名称后保存是更新当前条目，不是另存为。名称旁给出简短
   说明；不按同名猜测条目 identity。同名的不同 id 在列表中仍是独立条目。
10. 列表、加载、成功和错误均有中英文目录文案。弹窗内可切语言，不丢选择、请求或
    状态。键盘可选择、打开、关闭，未忙时 Escape 关闭，焦点回入口。窄屏与长名称
    自动换行，不横向溢出。没有删除、批量操作、搜索或版本选择器。

## 恢复语义

现有 `_load_recipe_entry()` 比较手动保存与自动保存的 timestamp，恢复适用的内容；
模型来自已保存 model_state，不执行 Recipe。步骤参数包含持久化 identity 与版图引用。
加载后 runtime statuses 重置为 Ready，逐步 snapshot cache 与 undo/redo 清空。
界面说明「已恢复保存的模型，逐步快照需重新构建后生成」，不把已有几何说成全步骤 Done。
孔口参考 Z 沿用既有加载失效规则，不根据模型、旧 UI 状态或输入参数猜测结果。

本段只连接当前服务已有的保存内容与版图引用；不打包/迁移附件，不承诺已缺失的旧图片
或外部 mask 文件可恢复。加载的结构来源、材料和版图 revision 必须通过实际 HTTP
测试验证，不用输入常量或 UI 行数冒充几何恢复证据。

## 接口和状态边界

| 既有接口 | 本段使用的契约 |
| --- | --- |
| `GET /api/history` | `ok:true,result:[{id,name,timestamp?,autosave?,note?,...}]`；id 非空且唯一，name 为字符串；未知扩展字段忽略，内部 file 不进入 UI；旧缺省可选值不臆造 |
| `POST /api/recipe/load` | `{id}`，id 来自列表；返回 `loaded:true`、权威 recipe/model/current_recipe，以及可选 ui_state/log；不改变既有别名 `/api/history/load` |
| `POST /api/recipe/save` | `{name}`；返回 `saved:true`，以及现有 id/current_recipe/recipes 元数据。只作 typed 加法透传，保留旧 client 的基本调用兼容性 |
| `GET /api/init` 与 `POST /api/timeline/get` | 只用于已有启动或明确的状态重新同步；不得借此触发运行、初始化或覆盖有效配方 |

实现时在 ARCHITECTURE_TARGET 的现有端点表中补充实际消费字段及命名 HTTP 测试，
不新增端点或改变旧响应。新解析器校验类型、空/重复 id 和布尔值；时间未知允许缺省。
服务端返回内部路径不构成前端请求地址，打开只发送 id，不拼接文件路径。

AppState 以可选当前配方元数据维护 id/name，启动、加载、新建、导入和保存使用服务端
权威值更新；旧 fixture/注入 API 缺少加法元数据时不虚构 id，也不靠名称绑定条目。
保存返回值可加法扩展，保留原 saved 字段。真实服务缺少必要成功元数据时明确显示
兼容性/状态提示，不把未确认身份作为有效当前条目。

列表读取有独立 AbortController 与请求代次：关闭、刷新、卸载或会话切换后的旧响应
不得回填。读取不改变模型、Recipe、历史或 preview generation；不进入工艺 running。
打开和保存共用 provider 同步写入 gate，从请求至必要对账结束持有，并在 action 内
再次核对连接、参数保存、活动草稿与类型候选。与导出、版图、步骤编辑和时间线双向互斥。
只读保存使用专用状态转移，不能复用会清除历史位置/错误的 run/started。

打开成功以现有配方整体替换路径提交模型与步骤，同时使用返回的 current_recipe；
随后只读更新时间线。时间线读取失败单独提示，不将已打开配方回退或报告为没打开。
加载的 ui_state 仅按既有应用规则消费，不强制恢复旧语言、相机或单位偏好。

## 错误与恢复

- 列表失败只在弹窗内显示，保留当前结构与输入，允许手动刷新，不自动重试循环。
- 明确服务端拒绝打开时，保留旧客户端内容与选择，显示打开失败，可刷新/重试。
  后端切换前保存当前内容是既有行为；错误文案不承诺完全没有磁盘写入。
- 打开请求的网络中断、超时或成功封套解析失败，可能意味着服务端已切换。此时明确
  标记「当前配方状态待确认」，禁止继续写入或导出旧模型；提供「重新同步」只读获取
  init/timeline，消费服务端权威内容。同步失败保持保护和错误，可手动再试，不重发打开、
  不自动重建。现有 bootstrap 为一次性动作，不能调用一个已完成即返回的空操作冒充同步。
- 保存异常不提示成功；网络不确定时提示「保存结果未确认」，允许显式重新保存。
  保存不切换模型，失败不得标记当前配方已保存或清空原步骤错误。
- 所有路径 finally 释放本次 controller/gate，卸载后不更新 UI。取消客户端等待不保证
  撤销已在服务端完成的保存或打开，不把取消描述为后端回滚。

## 自检与界限

本段复用现有持久化与加载语义，前端不计算几何、不读取服务器文件、不另造配方存储。
列表时间和自动保存字段不推断不可证明的最后手动保存时间；加载不制造旧快照或可信
执行结果。错误恢复只读对账，不重放写请求。方案 A 不含完整工程包、删除或物理仿真。
主工作树与用户未跟踪文件不变；不访问第三方 origin，不自动重启现有服务。
