# Studio 首次启动默认结构工程

日期：2026-10-23。所有者已确认：全新 Studio 会话只创建晶圆，已有工程优先恢复。

## 范围与验收

- `tcad_studio.py` 启动的全新会话只有一个晶圆初始化步骤。复用现有 `Initialize Wafer`，与「新建项目」保持兼容；它不调用工艺物理求解器。
- 首次可见的模型必须与晶圆参数一致；小 domain 保留生长空间，不出现声明厚度与实际硅块不符。使用既有新建项目的半高度规则，仅影响无用户输入的初始默认值。
- 恢复优先级保持不变：会话指定的项目、autosave、最近历史；有效旧仿真配方、结构配方、空配方及未保存草稿均不自动迁移或替换。
- 通用 `WebUIServerManager` 默认仍使用旧十步配方；启动器显式选择结构入口。多进程和 in-process fallback 必须传递相同选项。
- 新选项为 keyword-only 的 `startup_recipe_mode`，只接受 `legacy`（缺省）与 `structure`。直接调用 worker 的旧五参数签名继续可用。非法 manager 选项在创建存储或工作线程前拒绝。
- 新建、删除当前配方的默认回退、旧 WebUI、既有 HTTP 与保存格式均不改变。不要在 React 中导入示例、替换恢复后的配方或计算几何。

## 实施方式

保持 `_webui_default_recipe` 不变。在启动恢复全部未成功时，才给既有初始化助手传入结构入口选择；复用晶圆工厂、材料规范化及 `ProcessModel.configure_domain`，同步 substrate 与厚度后，仅调用一次既有 `InitializeWaferStep.execute` 初始化实际晶圆，不调用物理求解器。删除路径仍调用助手的旧缺省行为。不增加第二套执行器、HTTP 端点或持久化格式。

前端现有 `isStructureFlow` 已识别只有 `Initialize Wafer` 的配方，因此本次不改 UI 判定、目录或布局。浏览器验收应出现 Structure CAD、空工艺列表和可编辑晶圆设置，不出现默认十步流程或物理配方助手。

浏览器验收发现既有项目设置会将导出的材料 ID 与名称型枚举直接比较，导致三个晶圆材料字段无效。获准增加一个独立修复：仅在 `ProjectSettings` 构造显示模板时，把有效材料 ID 按当前材料表映射成声明选项支持的名称。已匹配选项的值保持原样；未知 ID 或不受选项支持的材料仍显示无效。原始导出、未编辑字段、SOI 参数和旧工艺步骤继续保留，不改变通用枚举校验或保存格式。

## 不在本次范围

不迁移用户现有工程，不修改物理仿真算法，不调整八类目录，不重构大文件，不修改其他面板提示，不自动合并、推送或重启所有者服务。
