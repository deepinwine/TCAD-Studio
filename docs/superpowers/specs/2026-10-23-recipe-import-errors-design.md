## 已核实的问题

`Toolbar.tsx` 的本地文件选择回调直接调用
`file.text().then(content => actions.importRecipe({recipe: JSON.parse(content)}))`，
没有捕获文件读取或 JSON 解析失败。解析发生在 provider 的 `importRecipe` 之前，
所以后者既有的异常处理无法接住这类失败。

以实际源码提取出的该回调进行纯运行时实验：输入 `{broken json`，产生未处理的
`SyntaxError`，导入动作调用数为 0。该证据是源码级复现，不冒称真实浏览器验收。
已有 Toolbar 测试仅覆盖本地 JSON 成功导入，没有这两个文件侧失败分支。

## 方案与边界

采用最小方案 A：工具栏持有本地导入错误的呈现状态，复用现有 `ErrorNotice`
组件和中英文目录；错误边界覆盖文件读取和 JSON 解析。解析成功后仍调用同一个
`actions.importRecipe`，由现有 provider 负责请求门禁、服务端错误与配方替换。

不采用方案 B 的导入预览／确认，不增加端点、依赖、前端 Recipe 校验器或后端算法。
不借用「TCAD 服务返回了无效 JSON」文案指代本地文件错误，也不调用语义无关的
`reportMaskError`。不调整全局错误、历史恢复、保存格式或现有错误映射规则。

## 可观察行为

1. 文件读取失败：显示「无法读取配方文件，请重新选择文件后重试。」及对等英文。
2. JSON 语法错误：显示「配方文件不是有效的 JSON，请检查文件后重试。」及对等英文。
3. 上述提示使用现有可访问的错误展示，不暴露文件内容、原始异常堆栈或本机路径；
   切换语言即时更新提示，不触发导入或重新加载。
4. 上述本地失败不发导入、保存、编辑或执行请求，不清空 Recipe、参数草稿、选择、
   既有执行结果或时间线，不刷新或重挂 Viewer。
5. 开始读取下一份已选文件时清除本地旧提示；文件选择器取消（没有文件）保持当前
   工程与提示不变。保留 input 值清空行为，让同一个文件可以再次选择。
6. 读取和解析成功后只调用一次现有导入动作。JSON 语法正确但配方语义无效时，
   仍由服务端校验并沿现有错误展示返回，不能误标为文件读取或 JSON 语法错误。
   不用本轮本地错误兜底覆盖服务端的结构化错误。
7. 本地错误提示不能永久禁用导入；失败后选择有效文件可以成功，再次失败仍能提示。
   保留现有互斥、未保存草稿与候选类型门禁，不绕过 provider 发请求。

「失败不改当前工程」专指请求发出前的本地读取／解析失败。请求已发出的失败、
网络不确定性与执行结果失效继续遵循现有 provider 语义，不在本轮承诺新的事务行为。
文件大小预算、独立取消按钮、读取进度、预览确认以及跨工程异步调度留在本轮范围外。
