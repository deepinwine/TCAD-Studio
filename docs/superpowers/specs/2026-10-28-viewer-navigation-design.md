# 查看器居中、导航立方体与窄屏修复

日期：2026-10-28。起点：已推送的 `main`（`bdf4468`）。
所有者已确认本段范围：补上「居中并适应窗口」和可点击面、棱、角的导航立方体，
同时修复窄窗口遮挡与保存模型恢复后的旧提示残留。
分支：`codex/viewer-navigation`；复用干净的隔离工作树。
本文件将已确认的交互整理为待审查的书面规格，不含实现。

## 目标与范围

让用户找回被平移、缩放到画面外的结构，并通过导航立方体切换观察方向。
改善窄窗口下的结构查看，不改变工艺算法、模型、API、保存格式或导出范围。
继续采用 React、Three.js 与现有相机和 OrbitControls，不引入新依赖。

本段交付四项内容：

1. 将现有「适应窗口」入口明确为「居中并适应窗口 / Center and fit」。
2. 增加随相机同步的导航立方体，支持 6 个面、12 条棱、8 个角，共 26 个方向。
3. 修正窄屏堆叠布局，使 3D 区域完整可达，不被底部时间线截去且难以滚动查看。
4. 当恢复后的会话已经产生有效逐步快照时，撤下旧的「需重新构建」提示。

不新增物理仿真、工程包、模型编辑工具、全屏系统、快捷键体系或视角持久化。
保留已有标准视图、投影、剖切、材料显示、测量与步骤眼睛功能。

## 当前实现与问题证据

- `ThreeViewer.tsx` 已将「适应窗口」接到 runtime 的 `fit()`，并有 7 个标准视图按钮。
  `viewerRuntime.ts` 的 `fit()` 保持当前视线方向，以完整已加载结构的 bounds 计算
  相机位置、观察中心和视锥。缺少直观的导航立方体。
- 当前坐标约定是 Z 向上：顶视 +Z、底视 -Z、前视 -Y、后视 +Y、左视 -X、右视 +X。
  新控件必须沿用这些约定，不能另造一套方向。
- 真实试运行页面在 712×915 视口中，workspace 为 y=145.5 至 823，步骤区高度约
  427.5 px；viewer 为 y≈573 至 1042，canvas 为 y≈686 至 1042。
  时间线从 y=823 开始，因此进入查看器时只能看到部分画布。workspace 虽可滚动，
  但画布上的滚轮由 OrbitControls 处理为缩放，不能把这种状态称为「已完整显示」。
  只读 DOM 证据：`/tmp/tcad-main-trial-JgVFRe/original-viewer-layout.json`；
  原页面截图：`/tmp/tcad-main-trial-JgVFRe/studio-trial-full.png`。
- `recipe/opened` 设置 `recipeOpened=true`，Toolbar 据此显示恢复提示。
  当前 run/timeline 更新未在有效快照产生后撤下该标记。真实页面中 6 个快照均有效，
  旧提示仍可见；这不是后端没有构建。

## 方案选择

| 方案 | 权衡 |
| --- | --- |
| 复用现有相机，增加轻量 SVG/DOM 导航控件（采用） | 无新依赖或额外 WebGL 上下文；方向与生命周期保持单一来源 |
| 新建独立 Three.js renderer 绘制导航器 | 增加第二个上下文、渲染循环和资源释放责任，本段没有必要 |
| 引入外部导航器包 | 增加依赖和相机适配成本，本段没有必要 |

导航器自身的投影和命中区域是界面绘制，不涉及半导体结构几何计算。
所有相机行为通过既有 runtime 边界执行；React 不读取模型体素或复制工艺算法。

## 居中入口

- 保留现有工具栏位置，使用清楚的中英文名称与可访问性标签。
- 点击后保持观察方向和正交/透视模式，将已加载完整结构放回观察中心并适配窗口。
  完整结构 bounds 与既有 `fit()` 一致；不因眼睛隐藏、材质显隐或剖切改变拟合范围，
  也不强行显示已隐藏的内容。
- 继续使用实际画布尺寸计算视锥。空模型、退化 bounds 或 WebGL 初始化失败时，
  沿用明确的默认/禁用处理，不出现 NaN 相机或异常缩放。
- 不清除剖切、透明度、步骤显隐、参数草稿、历史位置和工艺错误，不触发构建或下载。

## 导航立方体

- 位于 3D 画布右上角，深色、平面配色、清楚的面文字及 X/Y/Z 方向提示。
  材料面板仍在另一侧；控件周围空白不阻挡画布操作。
- 面指向对应的 6 个正视方向；棱指向两轴等权的斜视；角指向三轴等权的等轴方向。
  共 26 个唯一方向，均由 -1/0/+1 的三轴组合表示（排除全零），归一化后使用。
  面文字与现有前后左右、Z 向上坐标一致。
- 点击方向沿用现有标准视图的居中适配语义：方向改变后完整结构仍在画面中。
  保留当前投影模式、剖切、材质、步骤显隐和其他编辑状态。
  顶/底等极点方向使用稳定的 up 基向量，反复切换不出现 NaN、意外翻面或滚转漂移。
- 只有当前可见的面、棱、角参与鼠标命中；背面的区域不得穿透抢占点击。
  悬停有高亮和明确方向标签，棱与角有可操作的命中面积。
  点击导航器不会同时触发模型拾取、测量或 OrbitControls 拖拽。
- 鼠标拖转模型、标准视图、居中及投影切换后，立方体均反映实际相机方向。
  从 runtime 的相机/controls 变化订阅方向，不以「最后点击了哪个按钮」冒充同步。
  相机状态在渲染帧中合并通知；静止时不建立持续运行的第二条动画循环。
- 26 个方向均有可访问的名称与键盘操作路径，焦点可见，Enter/Space 可激活。
  中英文切换只改文字，不重挂 renderer 或重置相机。
- runtime 接口只作加法扩展；已有标准视图和测试注入路径保持兼容。
  卸载时清理方向订阅、监听与待执行帧，不留下回调更新已卸载组件。

## 窄窗口布局

- 宽屏保留现有「步骤—查看器—检查器」及可拖动分栏。
- 在既有 ≤900 px 断点内，优先为查看器安排完整可视区域，再提供步骤与参数区域。
  使用现有区域的响应式排布，不通过卸载/重建查看器实现顺序变化。
- 查看器的布局高度、canvas 尺寸、相机 aspect 与 ResizeObserver 使用同一实际区域。
  让普通尺寸的窄窗口首次显示时即可看到完整画布；流程、检查器和长内容仍可滚动访问。
  对不足以容纳所有内容的矮窗口保留清楚的滚动路径，不用 overflow:hidden 永久裁去控件。
  画布继续支持滚轮缩放，但进入步骤、参数和时间线不要求在画布上滚轮操作。
- 工具栏可换行，导航器不压住主要操作；保留时间线独立区域。
  响应式调整、打开配方菜单、状态文案换行、检查器折叠/展开均不得使画布落入时间线背后。
- 不通过裁短步骤列表内容、隐藏检查器字段、移除时间线或清除状态提示来规避布局问题。
  CSS 修改集中于相关规则，不进行整份样式表整理。

## 恢复提示生命周期

- 成功打开保存模型后，仍如实说明逐步快照尚未恢复；不把步骤标为 Done，不自动构建。
- 以当前会话权威 timeline 的 `snapshotValid` 为证据：至少一个对应当前配方步骤的
  有效快照产生后，撤下这次打开操作的旧提示。单纯发出构建请求不等于已有快照。
- 空 timeline、构建尚未完成、构建失败且没有有效快照、timeline 读取失败时，不伪造
  完成信息。部分成功且确有有效快照时可以撤下旧提示，原工艺失败仍必须保留。
- 只读 timeline 刷新、成功保存、语言切换不能清除保存成功反馈或原步骤错误。
  后续新建/导入/重新打开仍走既有身份、generation、写入 gate 和状态替换规则。
  旧会话的迟到响应不能撤下新打开配方的提示。
