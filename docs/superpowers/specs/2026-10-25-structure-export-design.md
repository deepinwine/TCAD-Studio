## 现状与方案

React 已有配方 JSON 和版图导出，但缺少结构导出入口。现有后端已提供
`POST /api/export` 与 `GET /api/export/download?file=...`，worker 的 `export_zip`
调用当前 ProcessModel 的 `export_3d_structure()` 打包，不执行 Recipe。
已有包包含合并 STL、拆分 STL、材料映射 CSV、XYZ 与表面高度 CSV。

采用现有 ZIP 路径，减少新格式与重复网格计算。单个 STL 下载不便保留材料拆分；
按屏幕可见部分裁切则与所有者本次选择不符，均不作为首版。

现有导出器可能自动附带 Agent 报告。新结构导出明确关闭该报告，以及可选截面和
工艺指标；旧客户端不传新选项时维持原行为。既有结构附属数据文件保持。

## 界面与用户流程

1. 工具栏增加「导出结构 / Export structure」入口，与「导出配方」区分。
   使用既有深色按钮和小型原生弹窗，不改三栏布局。
2. 弹窗说明导出完整的当前已构建模型，按材料拆分，STL 坐标使用 µm；
   隐藏材料／步骤、透明度、相机和剖切都不改变导出范围。
3. 不要求当前 Recipe 的所有后续步骤都已运行，不隐式构建。若有已修改、错误或
   尚未构建步骤，显示「仅导出当前已构建结果，未重新构建的修改不会包含在内」，
   并要求勾选确认后才能点击「导出当前结构」。初始只含晶圆的模型同样如实提示。
   提示不声称当前模型等于配方最终结果，也不触发保存或清除旧工艺错误。
4. 当前正在查看历史快照时，明确显示对应步骤；导出该快照的完整当前模型，
   不切回最新模型，不修改时间线位置或执行结果。
5. 有活动参数草稿、未完成保存、类型候选、运行／其他写请求，或未建立连接时禁用
   导出并给出原因。导出开始时再次检查门禁，双击只启动一个打包／下载流程。
   非活动字段草稿不新增阻塞规则，沿用现有活动字段判断。
6. 确认后显示「正在打包」「正在下载」。打包期间与 Recipe 写入、运行、历史恢复
   互斥，保证包与确认时的模型一致；查看器保持挂载，相机、可见性和单位偏好不变。
   不把打包当作工艺运行，不清空历史视图、步骤错误、孔口参考结果或几何 revision。
7. 成功后触发一个 ZIP 下载并释放浏览器临时 URL。服务失败、下载失败或文件内容
   无有效 STL 时显示明确错误，保留弹窗，可由用户点击「重新导出」重试。
   不自动循环重试，不自动执行工艺；重试前重新确认当前模型状态。
8. 中英文文案和可访问名称均由目录提供；弹窗可键盘访问、错误可读、关闭后焦点
   返回入口。语言切换不丢状态，窄窗口和长文件名不造成横向溢出。

## API 与兼容边界

- 复用现有两个端点；React 增加类型化请求／响应校验和 Blob 下载，不在 JS 中生成
  或裁切几何，不新增几何导出引擎或依赖。
- 结构打包请求固定 `sti=true`、`cross=false`、`metrics=false`、
  `merge_same_materials=true`、`include_agent_report=false`。同材料的不同连通部分
  可在同一 STL 内保留独立表面；合并兼容 STL 继续存在。
- `include_agent_report` 为既有打包端点的可选布尔加法字段，缺省保持旧的附带报告
  行为。此字段只控制附加报告，不改变模型、网格、Recipe 或旧调用的导出格式。
  同一变更更新 ARCHITECTURE_TARGET 契约及实际 HTTP 测试，不修改既有协议语义。
- 校验响应的 `zip_file` 是非空、安全的 ZIP 基名；只据此构造下载 URL，不将返回的
  staging 绝对路径用于请求或页面。保留 `files` 的类型化清单，确认有 STL，空几何
  不能以只有高度 CSV 的包冒充成功结构导出。下载必须成功且为非空二进制。
- 导出门禁复用现有 provider 并发控制，可增导出操作状态；其状态转移须保留历史
  模型与只读执行结果。不得沿用会退出历史模式或失效执行结果的运行动作副作用。
- 失败只报告导出错误，不覆盖已有步骤执行错误，不触发运行／重载对账；卸载时
  取消客户端等待并释放资源，不承诺取消已经在 worker 内开始的打包。

## 数据与能力说明

STL 是网格交换文件，不是可编辑工艺配方或精确 BRep 实体。STL 本身不嵌入单位，
因此界面明确说明 µm；配方 JSON 仍通过原入口导出。
本段复用现有网格提取、平滑和面数策略，不承诺无损体素边界或无面数上限；
不为导出改变网格算法、精度设置或 EDA 风格查看器。所谓「完整」是整个当前模型
与全部材料，不表示恢复已被刻蚀删除的材料或忽略既有网格质量策略。

导出会写会话临时文件并沿用既有导出包清理策略，但不改变正式模型、来源、
Recipe、snapshot、undo/redo、mask 资产或项目保存。正式用户存储不用作测试目录。
