## 已核实现状

`validateParameter()` 已返回有限值、整数、安全整数、上下限、正数、枚举、布尔值和
后端不支持等明确的 messageKey。普通 ParameterPanel 已按这些结果显示原因，
但上下限文案使用 canonical 数字，不含当前显示单位。

新增步骤、右侧类型候选和项目设置共用 AddStepDialog；该表单目前把所有字段错误
统一显示为「请输入符合范围的有效值」。已有 `aria-invalid` 主要用于数值输入，
错误文本尚未通过唯一 `aria-describedby` 与对应控件绑定。

保留两种既有交互：普通参数区自动保存有效输入；共用表单仅在确认后提交完整候选。

## 可观察行为

1. 活动字段非法时，在该字段旁显示已有校验结果对应的具体原因。例如负深度显示
   「必须大于或等于 0 nm」，大于 90° 的侧壁角显示「必须小于或等于 90°」，
   非数值显示「请输入有限数值」。中英文目录提供相同语义。
2. 上下限转换到该字段当前显示单位：例如 canonical 上限 1000 nm，在 µm 模式下
   显示「必须小于或等于 1 µm」。没有可靠换算元数据时沿用原 `spec.units`；
   没有单位的字段不虚构单位。切换语言或单位同步更新提示，不改变校验边界。
3. 提示数值不使用字段显示精度进行破坏性舍入；例如 90° 换为 rad 不写成精确
   「≤1.57 rad」而排除本来合法的值。换算结果不可有限表示时，回退明确标注的
   canonical 数值及其单位，不能把 canonical 数字贴上当前单位。
4. 整数／安全整数错误仍按真实 canonical 校验解释，不能暗示显示单位的数值一定要
   为整数。正数、枚举、布尔和不支持能力使用对应已有错误原因；转换溢出继续显示
   有限数值错误，不让组件崩溃或擅自纠正输入。
5. 共用表单的非法字段控件和错误文本使用唯一 ID 关联；数值、选择、布尔及方向性
   滑块如有错误，都保持正确的无障碍错误标记。多个候选不能共享错误文本 ID。
6. 修正值后对应提示消失，符合其他既有条件时确认重新可用。非法输入不提交；
   合法确认仍只发一次既有原子请求。普通参数区仍沿用既有保存时机和请求门禁。
7. 语言切换、候选切换和修正错误不丢输入、单位偏好、自定义名称或隐藏字段草稿。
   非活动字段继续不显示和不参与校验，不因本段增加跨字段校验或解析未来几何。

## 实现边界

- 复用 `parameterValidation.ts` 的结果与 `units/` 换算；可将 ParameterPanel 现有
  私有文案映射提取为共享的纯呈现 helper，供普通参数区和 AddStepDialog 使用。
  helper 只产生文案，不重新校验、不修改值、不发请求。
- 生产范围为 AddStepDialog、ParameterPanel 中的错误呈现、必要的共享文案 helper
  和双语目录。不改校验器规则、ParameterSpec、单位换算算法、候选提交结构或
  onConfirm 生命周期。不重构整个表单，不新增依赖。
- 保留既有 `failed` 服务端提交失败提示和 ErrorNotice；本段不翻译任意原始异常，
  不改网络重试或状态对账。自定义名称继续现有 80 字符限制，不新增名称校验体系。
- 不修改 Python、API、Recipe、保存格式、步骤身份、版图、Three.js、相机、几何、
  后端能力或正式用户数据。现有深色布局与控件类型保持。
- 无新架构决策；遵循 ADR-024 的双语与 ADR-025 的 canonical 单位边界。

本段只改善已有校验的可理解性，不增加校验能力；将单位转换、舍入和转换溢出的
提示约定写明，避免改了文案却误导合法边界。共享 helper 只承担呈现职责，
原请求门禁、活动字段和草稿生命周期不变；没有未定义接口或参数迁移。
